## Purchase and revenue data: validating the metrics

### Reviewing the daily data
**Definition:** Metric validation means checking whether the data you have is complete and suitable for the analysis you want to do, before you start calculating.
**Class example:** The class reviewed the daily data section for August and September. It contained checkouts, purchase counts and revenue values, and the question was whether these metrics are enough to identify where users drop out and how well the site converts.
**Business example:** An Indian D2C brand such as boAt or Mamaearth tracks daily sessions, checkouts, orders and revenue in Google Analytics 4 or Shopify reports. Analysts first confirm that the numbers line up (for example, orders never exceed checkouts) before using them in a funnel report.
**Remember:** Each funnel stage should have fewer users than the stage before it. If a later stage shows a higher number, check the data before you calculate anything.
**Exam tip:** In any analytics answer, state your data period (here, August and September) and list the metrics you used. It shows the examiner your analysis is grounded.

### Session as the base metric
**Definition:** A session is a single visit to the website. In class it was confirmed that, for this project, a session represents one unique visitor.
**Class example:** Santanu Paul asked whether "sessions" meant total visits or unique visitors. The answer was that a session is taken as one unique visitor, so sessions became the base number for all rate calculations.
**Business example:** On Flipkart, one shopper who opens the app in the morning and again at night creates two sessions in Google Analytics, though they are one user. Reports separate "Sessions" from "Users" for this reason.
**Remember:** (textbook) In Google Analytics 4, sessions and users are different metrics. One user can create many sessions. For this project, follow the class convention and treat each session as one visitor, but mention the difference if a theory question asks.
**Exam tip:** Always say clearly what your denominator is. A rate is meaningless if the reader does not know whether it is per session or per user.

## Funnel calculations

### Conversion rate
**Definition:** Conversion rate is the percentage of sessions that end in a purchase.
**Formula:** Conversion rate (%) = (Number of purchases / Number of sessions) x 100
**Class example:** Santanu Paul asked what baseline to use for conversion rate. The faculty clarified that you divide purchases by the session number and multiply by 100.
**Business example:** If Nykaa records 2,00,000 sessions in a day and 4,000 orders, its conversion rate is (4,000 / 2,00,000) x 100 = 2 percent. Indian e-commerce sites usually report conversion in the 1 to 3 percent range (textbook).
**Remember:** Purchases go on top, sessions go at the bottom. Do not use checkouts as the denominator for overall conversion rate.
**Exam tip:** Show the formula, substitute the numbers, and write the final value to three decimal places, as agreed in class.

### Drop-off rate
**Definition:** Drop-off rate is the percentage of users lost between one stage of the funnel and the next.
**Formula:** Drop-off rate (%) = ((Users at earlier stage − Users at next stage) / Number of sessions) x 100
**Class example:** Santanu Paul explained the method for the first phase: subtract the next stage's number from the earlier stage's number, divide by the number of sessions, and multiply by 100. The drop-off for the first phase came to 30.315 percent.
**Business example:** If Myntra has 1,00,000 sessions and 40,000 of them view a product page, then 60,000 visitors left before reaching a product. The first phase drop-off is (60,000 / 1,00,000) x 100 = 60 percent. Myntra would then test better home page banners or search to reduce this.
**Remember:** (textbook) Many analysts divide by the users at the earlier stage instead of total sessions. That gives stage-to-stage drop-off. Dividing by sessions, as done in class, shows each phase's loss as a share of all visitors, so the phases can be compared on one base.
**Exam tip:** Calculate drop-off for every phase, then name the phase with the highest drop-off as the main problem area and suggest a fix for it.

### Rounding standard
**Definition:** A rounding standard is a fixed rule for how many decimal places you report, so that all figures are consistent.
**Class example:** The class decided that all numerical calculations will be rounded off to three decimal places, which is why the first phase drop-off was reported as 30.315.
**Business example:** Swiggy and Zomato investor reports present conversion and order metrics in a consistent decimal format across quarters so that small changes can be compared.
**Remember:** Round only the final answer. If you round middle steps, the final figure can shift.

## What the faculty stressed

- Check that your data (sessions, checkouts, purchases, revenue) is enough for the analysis before you calculate.
- Use sessions as the base for both conversion rate and drop-off rate in this project.
- Conversion rate = purchases / sessions x 100.
- Drop-off for each phase = (earlier stage − next stage) / sessions x 100.
- Round every result to three decimal places.

## Practice questions

**Q1.** Define a session and explain how it differs from a user.
**A:** A session is one visit to a website. In class, a session was treated as one unique visitor for the project. In Google Analytics 4, however, one user can create many sessions, so the two metrics are reported separately. Always state which one you are using as your base.

**Q2.** A website has 50,000 sessions and 1,200 purchases in September. Calculate the conversion rate.
**A:** Conversion rate = (1,200 / 50,000) x 100 = 2.400 percent. Purchases are the numerator and sessions are the denominator, as clarified in class. The answer is rounded to three decimal places.

**Q3.** Write the formula for drop-off rate as used in class and explain each part.
**A:** Drop-off rate = ((users at earlier stage − users at next stage) / number of sessions) x 100. The subtraction gives the number of users lost in that phase. Dividing by sessions turns this into a share of all visitors, and multiplying by 100 makes it a percentage.

**Q4.** A site has 20,000 sessions. 13,937 users reach the product page. Find the first phase drop-off.
**A:** Users lost = 20,000 − 13,937 = 6,063. Drop-off = (6,063 / 20,000) x 100 = 30.315 percent. This matches the class figure and shows close to a third of visitors leave before reaching a product.

**Q5.** Why should you validate metrics before building a funnel analysis?
**A:** Validation confirms the data is complete and logical, for example that purchases do not exceed checkouts. Wrong or missing data gives wrong conversion and drop-off rates, which leads to wrong decisions. In class, the August and September daily data was checked first to see if checkouts, purchases and revenue were enough.

**Q6.** Why is a common rounding standard important in analytics reporting?
**A:** It keeps all figures consistent so they can be compared fairly across phases and months. The class used three decimal places. You should round only the final answer so that errors do not build up across steps.
